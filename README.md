# Japan (TSE) Valuation Screener

Finds Tokyo-listed companies trading below their industry peers, below
absolute value thresholds, or below their own filed history — and that still
earn a return on equity.

Third market in the family, after
[Korea](https://github.com/shkon1215-netizen/korea-screener) and
[the UK](https://github.com/shkon1215-netizen/uk-screener). The valuation
engine (`screener.py`) is shared and unmodified; everything else is Japan's.

## Quick start

```bash
python -m venv .venv && .venv/Scripts/activate      # Windows
pip install -r requirements.txt

python test_japan.py      # offline, no network
python check_setup.py     # nine live checks, ~1 min
python main_jp.py -v      # full run, 8-12 min cold
```

Live, rebuilt each weekday at 16:30 JST: **https://shkon1215-netizen.github.io/japan-screener/**

Or locally: open `jp_dashboard.html`. Or double-click `dashboard.cmd`, which starts a local
server and gives the dashboard a working Refresh button.

## What it screens

Universe: every domestic common line on Prime, Standard and Growth, with market
cap ≥ USD 600M and median daily traded value ≥ USD 4M. That is 3,707 listings
down to 661.

Three independent tests; a name passes if it clears any one of them.

| Screen | Test |
|---|---|
| **Cheap vs peers** | ≥20% below the industry-peer median on ≥2 of PER, PBR, EV/EBITDA. Peers are `33業種 × board`, winsorized median, excluding the stock itself. |
| **Cheap outright** | PBR < 1.0 **and** EV/EBITDA < 8, plus PBR below fair value (ROE ÷ 8% cost of equity), dividend yield ≥ 2%, ROE ≥ 5%. |
| **Cheap vs own history** | Today's PER **and** PBR ≥30% below the median of the company's own filed years. |

An ROE floor of 5% applies to all three, after scoring rather than before. A low
multiple on a company that does not earn its cost of capital is arithmetic, not
a mispricing.

## Where the data comes from

All free, no account needed.

| Source | Gives |
|---|---|
| **JPX** `data_j.xlsx` | Roster, market segment, official 33業種 classification, TOPIX scale. Also separates ETFs, REITs, PRO Market and foreign listings into their own categories, so they never enter the universe. |
| **JPX** market alerts | 監理銘柄 / 整理銘柄, by code. |
| **Yahoo! Finance Japan** | Market-cap ranking, sorted descending — the whole cross-section above the floor in ~20 requests. |
| **kabutan** | Per ticker: four filed years of P&L with EPS and DPS, three of balance sheet with BPS, three of cash flow, plus ROE and the company's own guidance. Blocks datacenter IPs, so it is local-only. |
| **yfinance statements** | The fallback, and what CI uses: five filed columns of income statement, balance sheet and cash flow. No company guidance. |
| **yfinance** | Batched daily volumes (liquidity) and monthly closes (own-history multiples); `.info` for EV/EBITDA. |
| **Frankfurter** | USD/JPY, deliberately on a different host from everything else. |

## Japan-specific things worth knowing

- **種類株式 are excluded.** TSE codes are four characters; a five-character
  code is a class or preferred line. There are seven, including 伊藤園's
  preferred (`25935`), which has traded 40–50% below the common for years for
  reasons that have nothing to do with the business.
- **The cost of equity is 8%, not 10%** — the Ito Review's figure, which is also
  what the TSE's below-book campaign is built on. Fair PBR is exactly 1.0 at 8%
  ROE.
- **`PBR < 1.0` is both well-calibrated and the exchange's own criterion.**
  Measured, it passes 20.3% of the universe.
- **kabutan's EPS is split-adjusted and its BPS is not**, which silently breaks
  the PBR history across any split. It is corrected from the split events that
  arrive with the price panel. yfinance restates both, so each source declares which. See invariants 11-12 in `CLAUDE.md`.
- **Forecasts are carried but never screened on.** Japanese headline PER is
  forward, struck on company guidance; every screen here runs on the last filed
  year, with the guidance alongside for context.
- **The published page and a local run use different sources**, because
  kabutan refuses datacenter IPs. They agree closely — BPS to 0.0% and EPS to
  1.2% on the median large name — but not exactly, and the published page has
  no guidance columns. `CLAUDE.md` has the measured comparison.

## Dashboard

One self-contained HTML file — no server, no build step, no external assets
beyond a webfont. Every threshold is adjustable in the browser and the verdict
re-computes live, because each row ships the inputs all three screens need.

Peer medians and anything below the run's market-cap floor cannot be
recomputed client-side, and the page says so.

Three delivery modes from one generator: opened off disk, behind `serve.py`
(Refresh button works), or published as a static site by `build_site.py`.

## Layout

`config_jp.py` thresholds · `providers_jp.py` data · `japan_filters.py` local
rules · `main_jp.py` CLI · `screener.py` shared engine · `dashboard.py`
generated by `sync_dashboard_from_korea.py`.

`CLAUDE.md` holds the invariants, the measured calibration table, the known
gaps and the failures to expect first. Read it before changing anything.
